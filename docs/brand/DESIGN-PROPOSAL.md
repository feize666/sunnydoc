## 二、v3 为什么丑 —— 三个可量化的真因

用户说「太丑」。我没有靠感觉改，而是把 v3 的渲染结果转成 ASCII 读出来，
定位到三个**具体且可复算**的问题：

### 真因 1：深色占比过高（37.1% @128px）

v3 描边宽 6.5，深色像素占 **37.1%**、黄只有 57.3% —— 整个图形被厚重的深棕
**框住**，黄色被闷在中间。ASCII 里整个外圈都是 `@`（深色）。
用户要的是「太阳要黄色可爱」，结果**深色成了主导**。

### 真因 2：光线是「深色方块」而不是光芒

v3 用「圆盘 + 3 根圆头棒」。棒与盘之间必须留净间隙，而描边会把间隙吃掉
`2×GROW`（两侧各外扩）—— 20px 下 GROW 只剩 0.65px，**间隙直接被抹平**。
实测光线视觉宽 15.5 / 长 6.0（长宽比 **1.39**，接近正方形），
ASCII 里就是**三个深色方块戳在头上**。

### 真因 3（最关键）：嘴的「弧深 / 线宽」只有 0.59

这是本轮最有价值的发现。v3 的嘴坐标本身没错，但：

```
v3: 弧深 4.10 / 线宽 7.00 = 0.59   ← 弧的弯曲量 < 线宽本身
v4: 弧深 8.50 / 线宽 5.20 = 1.63   ← 弯得出来
```

**比值 < 1 时，线宽会把曲率完全盖住 —— 无论坐标多精确，渲染出来都只是一根粗棒。**
这就是「明明算对了但看不出在笑」的根本原因。

另外眼睛只是 r=4.8 的纯色圆点（占脸径 19.2%），且**没有高光** —— 在 20px 下
就是两个黑点，必然显呆。

## 三、v4 的四项修正

### 1. 光芒：分离圆头棒 → **连续尖角轮廓**

改为极坐标连续波浪，一条闭合曲线：

```
r(θ) = R + AMP · ((1 + cos(N·θ)) / 2)^P
```

| 参数 | 取值 | 说明 |
|---|---|---|
| `R`（谷） | 26.0 | 脸盘半径 |
| `AMP` | 9.0 | 尖角高度；谷/峰 = **0.743** |
| `N` | 8 | 尖角数量；相位 0 → 正上/正下各一个尖角 |
| `P` | 2.4 | 尖度；P 大 → 窄而尖，P=1 → 平滑花瓣 |

**为什么这样就解决了真因 2**：凹凸随尺寸**等比缩放**，20px 下依然分得开；
且描边沿整条曲线连续走，**不存在内部缝合线**（分离式光芒的死结）。

### 2. 描边：6.5 → 3.0

深色占比从 **37.1% → 8%** 左右，黄色重新成为主导色。
20px 下 0.60px、32px 下 0.96px，仍能勾出轮廓。

### 3. 嘴：按「弦宽 + 弧深」反推，比值可控

| 参数 | 取值 |
|---|---|
| 弦宽（两嘴角距离） | 17.5 |
| 弧深（矢高） | 8.5 |
| 线宽 | 5.2 |
| **弧深 / 线宽** | **1.63** ✅（≥1.5 才读得出上弯） |

### 4. 眼睛：纯色圆点 → 竖椭圆 + 白色高光

| 参数 | 取值 | 20px 下 |
|---|---|---|
| 椭圆 | 9.6 × 12.6（占脸径 18.5%） | 宽 1.92px |
| 眼间距 | 21.0 | — |
| 高光 | 半径 = 眼宽 × 0.36，偏左上 | 0.69px（32px 下 1.11px 可辨） |

高光是「有神」与「呆滞」的分界。20px 下物理上读不出（0.69px），
但 32px 起可辨 —— 而 32px 是首页顶栏的真实尺寸。

## 四、设计规格（全部是量出来的）

### 配色

| 元素 | 取值 | 对比度 |
|---|---|---|
| 太阳黄 | `#FFD93D` | 对白底 1.38 · 对深底 **13.59** |
| 描边 | `#7C2D12` 深棕 | 对白底 **9.37** · 对黄 **6.80** |
| 五官 | `#4E342E` 深暖棕 | 对黄 **8.22**（无需额外描边） |
| 腮红 | `#F4511E` @ 42% | 叠加后 `#FAA030`，对黄可见但不抢眼 |

### 透明底为什么能跨主题成立（物理约束，不是审美选择）

黄对白底只有 **1.38**（几乎看不见边界），必须靠深棕描边勾形。实测：

| 元素 | 浅色底 | 深色底 |
|---|---|---|
| 黄太阳 | 1.38（看不见） | **13.59**（极清晰） |
| 描边 | **9.37**（清晰） | 2.00（变暗，无害） |

⇒ **两种主题的「轮廓提供者」不同，但都成立**：浅色靠描边、深色靠黄↔深底的强对比。
所以**一份 SVG 就够，不需要两套资源**。

### 各尺寸可辨性（20px = 顶栏 / AI 助手的真实尺寸）

| 元素 | 可辨下限 | 本方案 @20px | 判据类型 |
|---|---|---|---|
| 眼睛 | ≥1.6px | **1.92px** ✅ | 点状（<1.5px 糊成一点） |
| 嘴线 | ≥1.0px | **1.04px** ✅ | 线状（亚像素仍连成线） |
| 腮红 | ≥1.6px | **1.60px** ✅ | 点状 |

> ⚠️ **点状与线状的下限不同，别照抄同一个数**：
> 线状元素在亚像素渲染下 1px 仍能连成一条，而点状元素小于 1.5px 就只是一个像素点。

## 五、设计过程中被否掉的方案（都留了记录）

| 试过的做法 | 为什么否掉 |
|---|---|
| 分离圆点光芒（12 颗） | 小尺寸下圆点被描边焊在脸上，读不出 |
| 分离细长棒（8 根） | 同上；且间隙计算漏了描边 |
| 星芒「花瓣」形（AMP=5.4） | 谷/峰 0.80，读成花瓣不像太阳 |
| 6 尖 / 10 尖 / 12 尖 | 6 尖在 20px 下光芒读不出；12 尖太碎。**8 尖最稳** |
| 尖角相位 22.5° | 正上方变成凹口，失去「向上发光」 |
| 高光半径 0.9×眼宽 | 盖住整只眼，反而更呆 |
| 描边用「膨胀层」而非 stroke | 膨胀法在尖角凹侧变厚、凸侧变薄；`stroke` 均匀且体积减半 |

### 🔴 两个架构性改进

#### 1. 几何只有一处定义

`sunny_geom.py` 是唯一来源，`gen_logo.py` / `gen_preview.py` / `export_geom.py`
全部从它 import。而 **Node 侧不再手抄常量**，改为读 `geom.json`。

> 上一版 `verify_brand_logo.cjs` 把 `discR/eyes/blushR` **硬编码**在 JS 里并注明
> 「改动需同步」。本次把几何从 v3 改成 v4 后那些常量全部失效，
> 脚本却**照样报通过** —— 因为采样点已落在图形之外，断言退化成
> 「拿背景色比背景色」。**同源才能自证。**

#### 2. 描边语义必须与 SVG 一致

`gen_logo.py` 的 PNG 曾用「膨胀法」（深棕打底 + 黄身盖上），而 SVG 用
`stroke-width`。前者描边**只往外长**、后者**以路径为中心** —— 两者粗细差一倍，
在尖角处最明显，导致「预览图与落地图不是一回事」。
现统一为：深棕 `body(+grow)` 打底 + 黄色 `body(−grow)` 覆盖 = `stroke` 同语义。

### 🔴 本轮踩过的两个「假通过」陷阱

1. **注入无效 ≠ 判据有效**：想造哭脸却只把 `MOUTH_BOTTOM` 平移 ——
   凸向根本没变（角区间才决定凸向），自检自然通过。改**反转角区间**才是真哭脸。
2. **判据恒真**：「嘴角比弧底高」用亮度比较，哭脸时两个探针会**同时**落到黄上
   → 永远通过。改判「弧底正上方 0.9×弧深 处必须是黄」才区分得开方向。
3. **注入破坏语法会被误读**：`<svg ><rect/>...` 把 `xmlns` 挤到后面 →
   SVG 解析崩溃 → 脚本不输出统计行 → 被我的解析误判成「判据漏过」。
   现已让无统计行明确报「脚本崩溃」。
